# 自提物流及送货单同步接口

业务规则唯一来源：[送货单业务逻辑规则](送货单业务逻辑规则.md)。每次执行先按[状态工具接口](processing-state.md)读取上次处理结果。

1. **自提原单 → 对应运输台账。** 用 `inventory-pending.py` 清点待处理自提图，识图并在四本运输台账及配送旧账中查重。按项目及完整单号确定运输单位，录入 `ledger_root` 下对应运输台账，验证并保存。已有运输行先核实，不重复录入。
2. **保存到文件1。** 运输保存验证后，将原单保存至 `primary_archive_root`（送货单（自提））的对应项目/运输单位目录，按映射选用实际运输单位文件夹；文件名为完整编号及原扩展名，核验哈希。
3. **图片同步到文件2。** 将同一原单同步至 `settlement_archive_root`（配送台账及送货单(总)）的对应项目/实际到货年份目录，核验图片一致，保留文件1原图。这一步只完成图片同步。
4. **运输数据 → 对应年份配送台账。** 两处图片验证后，按 [配送接口](distribution-workflow.md) 选择对应年份配送工作簿；以磁盘已保存运输明细为来源，核对采购、入库余额、新旧配送记录，只补确认缺失数据，再验证保存。不能把图片已同步标为配送数据已录。
5. 保存释放按save-close-workflow.md。步骤2–3的新自提双归档CSV见manifest-schema.md，先预检再Execute。已有文件1原图的补同步只补文件2副本，不删除文件1原图。恢复时按上次处理结果和实际文件逐阶段核实，从未完成步骤继续；待处理图为空也要保留历史未同步事项。
6. 涉及Excel实时工具时先发现当前schema，不能猜旧会话参数。Office.js复制用destination.copyFrom(source, copyType)，不要使用source.copyTo。写前读取目标范围及相邻模板，写后逐字段及公式回读。运输、文件1、文件2、配送数据、保存及源清理各阶段独立记录。
